# "Skip the room — View résumé" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A visible "Skip the room — View résumé →" link on the room's first screen that opens the flat desktop with Internet Explorer already showing the homepage.

**Architecture:** A real `<a href="?mode=flat&open=resume">` is created by `main.js` before the room's dynamic import, outside the room's own DOM, and hidden while the monitor is focused. Flat mode reads `open=resume`, fast-boots (no BIOS/logo/welcome) and launches `iexplore`. Plain `?mode=flat` is unchanged.

**Tech Stack:** Vanilla JS (ES modules), Vite, Vitest + jsdom. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-15-skip-room-design.md`

## Global Constraints

- Link label is exactly `Skip the room — View résumé →`; no retro jargon.
- Link href is exactly `?mode=flat&open=resume` (relative, so the base path `/Portfolio/` is kept).
- Do not modify `src/room/mount.js` or any other `src/room/*` file.
- Plain `?mode=flat` (no `open`) must behave exactly as today, including the "3D room needs a desktop browser" notice.
- The existing 295 tests must keep passing; run `npm test` at the end of every task.
- Never commit or push unless Stephen says so. Commit steps below are checkpoints: ask first, then commit with the repo's `type: summary` style and the attribution lines the session specifies.

## Review Focus

- `?mode=flat&open=resume&utm_source=linkedin` (extra params) still opens the résumé. Pinned in Task 1.
- `?open=resume` on a capable desktop lands in room mode and simply ignores the flag, with no error. Pinned in Task 4 (browser check).
- Calling `powerOn({ fast: true })` when the PC is already on or booting does nothing, and the IE launch happens once. Pinned in Task 2.
- The link must not cover the XP desktop's top-left icons once the monitor is focused: hidden on `screenFocused`, shown again on `screenLeft`. Pinned in Task 3.
- If the room fails to start and `main.js` falls back to flat, the skip link disappears with the rest of the room UI instead of lingering. Pinned in Task 4 (browser check).
